# decisions.md

- **Context:** project language and tooling choice.
  **Decision:** Vite + TypeScript, vanilla DOM (no framework), npm,
  Vitest + happy-dom, ESLint + Prettier, GitHub Actions CI.
  **Alternatives considered:** Svelte, React. **Decided-by:** planner.
  **Status:** Accepted in PR #1
- **Context:** PWA icons.
  **Decision:** single SVG source `public/icon.svg`; PNG copies are
  generated by `scripts/generate-icons.mjs` (sharp, dev-only) and
  committed to `public/icons/`; CI does not regenerate icons.
  **Alternatives considered:** hand-made PNGs. **Decided-by:**
  planner. **Status:** Accepted in PR #1
- **Context:** dependency versions (the card fixes the package list, not versions).
  **Decision:** all 8 packages in devDependencies (no runtime deps; vite is the
  dev/build tool), pinned to a mutually compatible set: vite ^6, typescript ~5.9,
  vitest ^3, happy-dom ^18, eslint ^9, typescript-eslint ^8, prettier ^3,
  sharp ^0.34; package-lock.json is committed so CI `npm ci` is reproducible.
  **Alternatives considered:** latest majors (vite 8, vitest 5, eslint 10,
  typescript 7), which conflict with the fixed list (typescript-eslint 8 peers
  eslint ^9). **Decided-by:** coding-agent. **Status:** Accepted in PR #1
- **Context:** "prettier compatibility" in the ESLint flat config with a fixed
  dependency list (eslint-config-prettier is not allowed).
  **Decision:** rely on typescript-eslint `recommended`, which enables no
  formatting rules, so Prettier (prettier.config.js: defaults + printWidth 100)
  never conflicts with ESLint. **Alternatives considered:** adding
  eslint-config-prettier (would break the fixed dependency list).
  **Decided-by:** coding-agent. **Status:** Accepted in PR #1
- **Context:** tsconfig include set ("include src and scripts typings via
  vite-env.d.ts").
  **Decision:** include ["src", "scripts", "vite.config.ts", "eslint.config.js"];
  src/vite-env.d.ts carries the vite/client reference; strict, ES2022 target,
  bundler moduleResolution, noEmit (tsc is the typecheck half of `npm run build`).
  **Alternatives considered:** a separate tsconfig.build.json.
  **Decided-by:** coding-agent. **Status:** Accepted in PR #1
- **Context:** PWA icon artwork (card says "your design", flat, no gradients, no text).
  **Decision:** gift box with bow, cream #f3e2c3 box + gold #d9a441 ribbon/bow on
  night-blue #0b1d3a, 512x512 viewBox in public/icon.svg.
  **Alternatives considered:** snowflake. **Decided-by:** coding-agent.
  **Status:** Accepted in PR #1
- **Context:** maskable icon generation and asset URL style.
  **Decision:** maskables render the SVG at 80% of the target size centered on a
  solid #0b1d3a background (safe zone); all asset URLs in index.html and the
  manifest are root-absolute (base '/'), and index.html additionally links the
  SVG as favicon. **Alternatives considered:** relative URLs, hand-made maskables.
  **Decided-by:** coding-agent. **Status:** Accepted in PR #1
- **Context:** where the header markup lives and the unspecified grid metrics.
  **Decision:** renderCalendar builds the header ("Dezember 2026" + subtitle
  "24 Türchen bis Heiligabend") and appends header + grid into the container without
  clearing it; index.html holds only #app. Grid: gap 10px, padding 16px, door radius
  14px, hover #1a3560, 120ms ease transition, content centered with max-width 1200px.
  **Alternatives considered:** header hard-coded in index.html. **Decided-by:**
  coding-agent. **Status:** Accepted in PR #1
- **Context:** manifest.test.ts must read files relative to the repo root, but
  happy-dom rewrites import.meta.url to a non-file URL.
  **Decision:** resolve the repo root via process.cwd() (vitest always runs from the
  repo root via npm scripts). **Alternatives considered:** import.meta.url +
  fileURLToPath (fails under happy-dom). **Decided-by:** coding-agent.
  **Status:** Accepted in PR #1
- **Context:** the `iterations` parameter of `deriveKeyBits` (the card fixes
  600000 for production but wants fast tests).
  **Decision:** `deriveKeyBits(name, password, saltBytes, iterations = 600000)`;
  the optional parameter defaults to 600000 and exists only so tests can run
  faster; production callers never pass it.
  **Alternatives considered:** a separate test-only derive function.
  **Decided-by:** coding-agent. **Status:** Accepted in PR #2
- **Context:** what the persisted session stores, and what happens when a
  stored session no longer decrypts the bundle.
  **Decision:** `wc.key` holds the base64-encoded derived key bits and
  `wc.name` the entered name; the password is never stored. A session that
  fails the silent decrypt falls back to the login and is overwritten on the
  next successful login.
  **Alternatives considered:** storing the password (rejected: the password
  itself would sit in localStorage).
  **Decided-by:** coding-agent. **Status:** Accepted in PR #2
- **Context:** the login lockout is client-side only.
  **Decision:** the delay ladder (2/4/8/16/32 s by failed attempt number,
  capped at 32 s) is a cosmetic fallback, documented as such in a comment in
  src/lockout.ts; its state lives in `wc.attempts` / `wc.until` and a
  successful login resets it.
  **Alternatives considered:** none feasible for a fully offline static site.
  **Decided-by:** coding-agent. **Status:** Accepted in PR #2
- **Context:** shared base64 helpers and the encrypt direction needed by tests.
  **Decision:** base64 encode/decode live in src/base64.ts and are used by
  crypto.ts and session.ts; the encrypt direction (only needed to build test
  fixtures) lives in src/test-utils.ts, which the app bundle never imports.
  **Alternatives considered:** exporting an encrypt function from crypto.ts
  (would widen the production API beyond the card).
  **Decided-by:** coding-agent. **Status:** Accepted in PR #2
- **Context:** placement of the welcome line relative to header and grid.
  **Decision:** renderApp inserts `<p class="welcome">` between the header and
  the grid via insertBefore, leaving renderCalendar unchanged.
  **Alternatives considered:** welcome line above the header.
  **Decided-by:** coding-agent. **Status:** Accepted in PR #2
- **Context:** URL used to fetch the encrypted bundle at runtime.
  **Decision:** `${import.meta.env.BASE_URL}content.enc`, so the fetch follows
  the configured vite base.
  **Alternatives considered:** hard-coded '/content.enc'.
  **Decided-by:** coding-agent. **Status:** Accepted in PR #2
